## What this is

Go library (`github.com/Luo-root/pulse`) — a **data-driven workflow execution core** (a reusable `Graph` **definition** + one `Execution` per run) plus a **graph-observation layer**. Nodes declare which keys they read and write; topology is implied by data production and consumption (no edge objects, no topological sort before execution, no local scheduler loop).

Product direction and cross-repo responsibilities: [`docs/design/workflow-foundation.md`](docs/design/workflow-foundation.md) ([#320](https://github.com/Luo-root/pulse/issues/320)). `pulse-durable` extends the core with checkpointed execution and, in later designs, durable waits and distributed run management. Planned capabilities are not implementation claims. Preserve the reusable definition / isolated execution model and one-way dependency: durable imports pulse, never the reverse; reliable submission/restoration primitives belong in the core, storage/Codec/run ownership belong in durable. The local data-arrival mechanism does not prohibit durable task claiming, wake-up scheduling or failover.

The engine is the root package `pulse`; `observe/` folds the engine's `Observer` callbacks into structured records; `yaml/` assembles graphs declaratively. **The engine's dependency closure is zero** (standard library only).

Release milestones (maintainer-confirmed, 2026-10-13): first complete Pulse capabilities, settle the Durable bridge contracts and pass end-to-end bridge integration before releasing Pulse **v0.5.0** and pulse-durable **v0.1.0**. The first-phase Durable plan is **v0.1.0**, not the final v1.0.0 freeze. Continue 0.x iterations afterward; breaking changes still require a minor, never a patch. Once the agreed project goals are achieved and no foreseeable major structural changes remain, complete the detailed documentation and release each repository's **v1.0.0**, largely fixing its public API and implementation. Keep essential godoc/examples/migration notes current before then. Stage completion does not trigger releases; merging and publishing are the maintainer's decision. MemoryStore validates contracts only; claims about surviving process exit require a real persistent backend and exit/restart tests.

go test -race -count=1 ./...

- No Makefile or linter config. GitHub Actions CI (`.github/workflows/ci.yml`) runs `go build ./...`, `go vet ./...`, a gofmt check (empty output = pass), plus the `-race` suite on every PR and on pushes to `main`.

Historical prose about the deleted Graph snapshot passes; copyable old calls in code fences fail. `ReadOutput(e, key)` (including explicit type arguments) takes an Execution plus a typed Key, never a Graph, RunCtx, Snapshot, or string key. Migrate README (中/英), `site/`, `docs/design/` and the package READMEs together, then re-run it. Its own positive/negative controls live in `TestDocsExampleGateNegativeControls`, and the walk fails if it scans fewer than `scanFloor` sites (a gate that silently stops scanning is worse than no gate).

## Key conventions

- **No `internal/` or `cmd/`** — this is a library, not a binary. All published packages are public API.
- **Chinese comments and doc are the norm**; preserve them when editing. **README naming**: `README.md` is the Chinese default, `README_en.md` is English — same for the root and every package (`observe/`, `yaml/`). The site builds from those two files.
- **Functional options pattern** throughout (`pulse.WithObserver()`, `observe.WithRenderer()`, `pulse.WithMaxRunning()`).
- **Dependency direction is one-way and must not reverse**: `pulse` ← `observe` / `yaml`. The engine never imports an observation package. Verify with `go list -deps .` — it must contain no other `github.com/Luo-root/pulse/*` entry.
- **Slot contract**: `pending` | `ready` | `skipped`. Skip is **arrival, not failure**; a node error cancels the graph and is never rewritten as skip. Unwritten `Provides` after a successful `Run` are auto-skipped.
- **Fan-in gate**: the gate is judged once every input has arrived (ready *or* skipped), and it asks "did any input bring a value" — a node enters `Run` as soon as one did (collect whatever arrives), and only skips itself when none did. A skipped input read inside `Run` yields `*SkipError`; returning `WaitAll`'s value is the explicit "all-or-skip me" opt-out.
- **Definition vs run (stage 2, landed)**: `Graph` is a **reusable static definition** — id / description / keys / producer table / ports / nodes / declared defaults — and holds **no** runtime state. Everything about one run lives in `Execution`: its own ctx and cancellation domain, input values, slots, per-node state, first error, waitgroup, and the **effective** observer / quota / graph-level aspects computed once at creation (this run's `ExecOption` > the definition's declaration > the parent execution's environment). `g.Run(ctx, in)` = `NewExecution` + `Start` + `Wait`, and it builds a **fresh** execution per call — so one definition can run many times sequentially, many times concurrently, and be mounted at several places at once. `ErrGraphStarted` covers two cases: a definition is sealed and rejects mutation, or the same **execution** is started twice; slots never reopen, and a second run means a second execution. `New` therefore no longer takes a ctx. **Do not add a `Reset`**, do not put runtime state back on `Graph`, and do not add public surface that assumes `Graph.Child *Graph` — cross-run state belongs to the caller.
- **Inputs: the declaration is the definition's, the value is the run's (stage 2, landed)**: `DeclareInput(k)` is the definition's promise that `k` may come from outside; the value for *this* run goes into an `Inputs` value through `pulse.Seed(&in, k, v)` / `pulse.SkipSeed(&in, k)`. A nil `Inputs`, a zero `Key[T]`, a `nil` value, and a **second** write for the same key are all rejected at that call — the second write would be silently dropped by the slot's idempotent first write, which is exactly the mistake worth catching. `Run` / `NewExecution` then judge the **start condition**, and only that: every inlet some node `Requires` must be accounted for this run (seeded, skip-seeded, or bound with `In` in the parent). Feeding an undeclared key, feeding a key the graph itself produces, and missing a required inlet are all rejected there, by name, instead of hanging until the ctx expires. That per-run judgment runs **twice**: at creation (early feedback) and again inside `Start`, immediately before the seal — a definition can still grow a new `Requires` in between, and the definition that was judged has to be the one that gets sealed and run (see the Start-validation bullet). An inlet nobody `Requires` does not force the caller to feed it — this is a per-run criterion, separate from `Validate`'s "is this definition structurally sound". A **declared inlet is always a real inlet**: `DeclareInput(k)` on a key a node of the same graph already `Provides` is rejected at that declaration, and `Add`ing a provider for an already-declared inlet is rejected at that `Add` — one judgment from both sides, both wrapping `ErrDuplicateSource` (a port like that could only ever be dead, since the feed above is exactly what gets rejected).
- **Object model (`#311`)**: static composition, the `Execution` split, transactional `Retry`, execution snapshots, observation identity, Mermaid and YAML Analyze are **implemented**. Stage 5 covers migration & release; releasing remains the maintainer's decision. `docs/design/pulse.md` describes **what exists today**, while `docs/design/object-model.md` preserves the settled contract, migration rationale and staged plan. Philosophy (why the trade-offs are what they are): `docs/design/philosophy.md`.
- **Composition is static — `pulse.Sub` is the only public entry (stage 1, landed)**: `pulse.Sub(g, id, description, binds, child)` mounts a **ready-made** child graph — ports (`DeclareInput` / `DeclareOutput` + `NewPort` / `PortRef`) are the *only* wiring surface, the whole subtree is visible **without running** (`Topology().Nodes[i].Sub`, path derived from the mount position), and the child's static problems surface at assembly time (in `pulse/yaml`: at `Load`, with the **mount path** in the message). There is **no** dynamic builder: the old `SubFunc` / `SubCtx` form is **deleted**, not renamed — a fresh child per run is what the stage-2 `Execution` now gives you (that is why deleting the dynamic form lost no capability). `pulse/yaml` builds one child **instance per mount site** at `Load`; at run time each mount site builds its own **child execution** (`newChildExecution`, ctx derived from that step's ctx, effective config computed from the parent execution's environment), so one child graph mounted twice runs **twice, independently** (own slots / first error / cancellation domain). Bind shapes are judged by `checkBinds` (shared by `Sub`, `Validate` and `Topology().Problems`): a child **inlet** may be bound with `In` **once** (a second `In` would be silently dropped by first-write-wins), and being bound through two entrances (`In` + `In`, or `In` + `Fix`) is the same "bound twice" error. **`Fix` / `FixSkip`** carry a value **for this mount site** — that is the only place a mount-site default can live, because it is not part of the child's definition (which is why the old seeding entry that took a child graph as its first argument had to go); a default *every* mount site wants belongs inside the child as a node that produces it. Binding an inlet the child produces **inside** is rejected at assembly time — `"k" is not a input port of the child graph` when the key was never declared an inlet (a key that only lives inside the child is its implementation detail) — and the state "declared inlet + produced inside" **cannot be built at all** (`DeclareInput` and `Add` reject it in both orders, `ErrDuplicateSource`; see the Inputs bullet), so `checkBinds` no longer carries that branch. Never a silent drop or a run-time surprise. `Out` is not deduped (two parent keys from one outlet lose nothing; the same parent key twice is rejected by `Add` as a duplicate `Provides`), so **`In(p, k)` + `Out(k, p2)` on one port is legal** — that is the pass-through (`k` declared as both inlet and outlet). **Every inlet the child actually needs must be fed at each mount site**: `checkBinds` also runs the reverse direction — an inlet some node inside the child `Requires`, or the only source of an outlet this site binds with `Out` (a pass-through, whose inlet can never be produced inside), has to be covered by `In` / `Fix` / `FixSkip`; otherwise the mount is rejected at assembly instead of failing later — at `newChildExecution` (`has no value for this run`), or for the pass-through at `bridgeOutputs` (`never arrived`), both after sibling nodes may already have run. An inlet nobody needs and no `Out` bind of this site depends on stays **optional** (another mount site's interface, or a port this site does not use): the obligation follows the promise, and `Out` is the promise. `retry:` on a `graph:` node is rejected at `Load` — the bridge back into the parent happens inside the first attempt and those slots are idempotent first-write, so a retry has no clean set of its own (per-attempt write sets are the next stage); put the retry on the node inside the child that may actually fail. On the Go side `Retry(...)` on a `Sub` step **works** (stage 3): retrying re-enters the step's body, every attempt builds a **fresh child execution**, and that attempt's bridge into the parent lands in that attempt's write set — so a failed attempt's parent-side outputs are discarded with it and the parent only ever sees the successful attempt's version. The step's **advance gate** still holds: a user-written retry-like aspect opens no boundary and is rejected on its second advance (the rejection also carries the first attempt's error).
- **Sealing**: `(*Graph).Validate()` **seals the whole subtree** when it passes — and a successful `(*Execution).Start()` seals it as well (same rule, same critical section) — the mounted children are part of this definition, so `Add` / `DeclareInput` / `DeclareOutput` / `Sub` are rejected on **every** graph of that subtree (the second trigger point of `ErrGraphStarted`; the first is starting the same `Execution` a second time). A sealed child can still be mounted elsewhere (mounting does not change it) — and it can still **run** there: sealing freezes the **definition**, it does not consume it (`sealed` and `started` are now two questions about two different objects — the definition is sealed, the execution is started; `TestSealedChildCanBeReusedElsewhere`). A **failed** validation seals **nothing**, in no layer — that is what "add the missing piece and validate again" needs. Do not add a `Seal()`. Seeding is outside all of this: `Seed` writes into this run's `Inputs`, which belongs to no definition, so the step no longer keeps a run-time seed guard — what the child's inlet sees is the mount site's `In` binding or its `Fix` value.
- **Assembly is one critical section (`assemblyMu`)**: every definition-mutating entry (`Add` / `DeclareInput` / `DeclareOutput` / `Sub`) and the "check the whole tree, then seal it" entries (`Validate` / `(*Execution).Start()`) share one package-level lock, and it is always taken **before** any graph lock. Two invariants need it: the **mount cycle** (a cycle is the composition of two graphs' separate actions — checking and mounting must be one step), and the **validate → seal boundary** (the check pass takes and releases each layer's lock, so without the assembly lock another goroutine can rewrite a mounted child in between and `Validate()` would return nil while sealing a structure it never checked — measured, first trial). Corollary: **a sealed tree is exactly the tree that was checked**. Keep `Validate` and the start path holding it across both passes; a failed validation still seals nothing.
- **The static checks recurse with per-layer locking**: `Topology()` / `Validate()` ask each child through `child.problemsWithStreamsAt` / `child.topologyAt`, which take the child's own lock — never read a mounted child's mutable fields while holding only the parent's lock (pinned by `TestSubChildAssemblyVsParentReadOnly`; `checkBinds` takes the child's lock for the whole batch, pinned by `TestCheckBindsReadsChildPortsUnderChildLock`). When the layer's lock is already held, use its `...Locked` variants; neither the locking wrapper nor `checkBinds` is re-entrant. The mount chain reports a cycle before recursive locking could overflow or deadlock. `problemsAtLocked` computes the whole-tree stream facts once, then recursion shares the resulting `streams` map rather than restarting the stream model at each layer. Effective quotas follow root ExecOption > definition declaration > inherited capacity, while stream participants are grouped by actual quota-pool identity, not equal numeric limits.
- **Declared outlets are checked statically** like inlets: `DeclareOutput(k)` where nothing in the graph provides `k` (and `k` is not also a declared inlet — an inlet/outlet pair is a **pass-through**) is reported by `Validate` / the start path / `Topology().Problems` at assembly time, naming the mount path when the graph is mounted, instead of waiting for `bridgeOutputs` to say `never arrived` after the child ran. A declared inlet for a key the same graph produces is rejected where it is declared (`ErrDuplicateSource`) instead. `Problems` order is sources → declared outlets → dependency cycles → streams → per-mount subtree; the outlet category is ordered by key name (map iteration must never reach a message).
- **In `pulse/yaml`, an unreferenced spec is not judged for missing sources**: it has no mount site, hence no interface — "nothing feeds this key" is undecidable there (an unknown source may become a future inlet in the build-only check graph). Known sources still participate: literal/skip seeds are declared in that graph and conflict with a same-key provider through the core's ErrDuplicateSource. Factory names / empty nodes / duplicate ids / known source conflicts / cycles / streams remain checked. Missing sources are judged per **reference site** once the spec is mounted.
- **Aspect advance gate (stage 3, landed)**: a node's `Run` must not be **entered concurrently** (overlapping `next` → `ErrNextCalledTwice`). Sequential re-entry is judged by a different question — **"did this advance come with a fresh attempt boundary"**: the first advance through a node execution passes; a second one passes only when the write target (`rc.writes`) has **changed** (which is exactly what `Retry` does per attempt), otherwise it is rejected with `ErrNextCalledTwice` and that message also carries the **first** advance's error. A user-written retry aspect is precisely this shape: it opens no boundary, so its second advance would silently merge two runs into one node. The ledger belongs to the **node execution context**, not to a node id — another `Execution` is a fresh context and its count starts at zero.
- **Attempt write set (stage 3, landed)**: `Retry` opens a **fresh `writeSet` frame per attempt** (`slot.go`; `outer` chains nested `Retry`s, `outer == nil` means "commit into the execution's slots"). Inside an attempt, `Set` / `Skip` land in that frame and never touch the execution slot; a failed attempt that will be retried **drops the whole frame**, so downstream never sees that attempt's output (the slots were never touched, so nobody was even woken). A successful attempt — or one that ends **skipped**, since a skip is arrival — **commits**: hand it to the outer frame if there is one, otherwise write per key into the execution slots, ordered by key name. The whole batch is **checked first** (`checkCommitTarget`: a target that already arrived in the opposite state is `ErrConflict`, the same state is the idempotent first write) and **if any key cannot land, nothing is published** — no "half a batch" state. That check rests on a **single sequential writer per output**, and the invariant is explicit here on purpose: the only engine paths that write an execution slot are (a) seeding at execution creation, before `Start` (and a key the graph produces cannot be fed as an input), (b) the node's own attempt chain — body / aspects / child-graph bridge all on one stack, pinned by `TestNodeWritesFinishBeforeTheChainReturns` (the chain does not return while a write or a ctx-ignoring body is still in flight) — and (c) its finish path (`settleUnwritten`, same stack). No other node can write it: a key has exactly one source (`Add` rejects a second provider with `ErrDuplicateSource`). So no third party can slip between the check and the write; **concurrent `Set` of the same `Provides` from a goroutine you started is outside the contract** (a single `Set` is safe on its own — slots carry their own mutex — but the all-or-nothing batch assumes one sequential writer). The check-then-write pass is still per key, so *visibility during* the commit is **not atomic** (the window is "one output `ready`, another still `pending`"); the hard guarantee is only "no failed attempt is ever visible". Two more consequences to keep straight: **a nested `Retry`'s inner commit lands in the outer attempt's frame**, so an inner success is not published until the outer attempt commits (if the outer one fails, the inner writes go with it); and the read path (`readTarget`) **peeks without creating an entry** — reading a key this attempt never wrote must find its real source, not a fabricated `pending` slot that would mask it; and the finish path (`settleUnwritten`) asks **`landed`** — "did this key land", not "did this node write it" (a discarded write must still end skipped, or its downstream waits forever). Boundaries: **a cross-attempt read does not see a discarded write** (that key never had a value in this attempt — it waits for a slot nobody will write), while a **read-back inside the attempt does** (staging wins); writes made by an aspect **outside** `Retry` belong to no attempt and are not discarded; only engine-managed slots are ever discarded, external side effects stay the caller's problem. And `Produce` / `Tee` **refuse to run under a write set** (`checkChannelVisibleNow`): a staged channel would only publish on commit while its consumer waits for it, so sender and receiver deadlock until the ctx expires — a named error now, judged by "is there a write set" and never by aspect identity (`Aspect` is a bare func type, unidentifiable at assembly time).
- **Start validation**: starting an `Execution` rejects the statically-knowable dead graphs — a `Requires` with no source, a **declared outlet nobody produces**, and a dependency **cycle** (every input has a producer, yet no node can run first). The **per-run** half of the story (every required inlet has a value for *this* run) is judged when the execution is created **and re-judged inside `Start`, immediately before the seal** — same criterion, word-for-word the same message. The definition can grow a new `Requires` in between (`Add` is still open), and `Start` is about to seal the very definition it judged, so "judged = sealed = actually run" stays one version. A rejected start still marks nothing started and seals nothing (feed the value and run again). Without those checks they surface as a hang, or as the runtime's fatal all-goroutines-asleep deadlock (or, for the outlet, as `never arrived` only after the child ran). A cycle is reported as one concrete path: `pulse: dependency cycle: A -> B -> A (A requires "y", B requires "x")`.
- **Input and binding validation (#336–#339)**: keyRef validity requires both a nonempty name and a real type at input/port/registry/bind entries. Get/TryGet accept ready nil only for interface T; internal In uses setArrived to preserve that arrival, while host Seed/Fix still reject nil interface. InRef/OutRef compare the actual reflect.Type at assembly. Parent Requires is deduplicated by name + type, in first-bind order, so one ordinary parent value may feed distinct child inlets; all binds remain and every child inlet still allows one entrance. Ordinary node duplicate Requires and duplicate parent Provides remain rejected.
- **Streams across composition (#334–#335)**: static checks copy nodes by mount site, trace channel aliases through In/Out/pass-through binds, count actual readers and partition quotas by pool identity (not equal numeric capacity); Sub occupies no slot. Same FanOut competition groups are recognized only within one mount. Known Produce/Tee outputs require actual readers, including declared root outlets. Known sync send/close, Consume completion, child completion and Wait-before-Out form a separate wait graph used only for validation. Report one concrete witness per cyclic component; do not add runtime scheduling or infer callback/Aspect hidden waits, manual channel close timing, or actual Fix channel pointer aliases. No-stream trees exit through a per-layer locked check; do not repeatedly copy unused port tables. Definite FixSkip and supplied skip inputs remain local to each check/mount; Start includes effective ExecOption/inherited Aspects, and Aspect outputs are not presumed skipped. Propagate each new fact through reverse Requires/bind indexes with a static worklist, never repeatedly scan all nodes; declaration order must not turn Start into quadratic work. Nested Topology views share this check's mount facts. Validate/Start keep the assembly boundary, Topology remains a non-atomic per-layer sample.
- **Observation**: every callback carries a `Site` — the definition's graph id, **this run's execution id**, and the mount path — so the same graph run twice, or mounted at two places, never folds into one set of records. Business dimensions go through `Attrs` only — **never add named fields to `Record`**. Attr keys use the `<component>.<field>` convention and are defined by the package that owns the fact (`pulse.AttrGraph` / `pulse.AttrNode` / `pulse.AttrExecution`).
- **Checkpoint bridge (#307, scheme A)**: `WithExecCheckpoint` enables complete-chain staging and synchronous confirmed-before-publish across the whole execution tree, independently of Aspects. `CheckpointNodes` / `CheckpointPorts` expose copied declarations with real reflect.Type; `CheckpointInputs` exposes only supplied external inputs. `RestoreNodes` replaces a verified whole plan; Start revalidates under the assembly boundary before installing any records or sealing. Recovered nodes emit only Finished, without running body/aspects/Commit or inventing children. Durable owns stable scopes/Store/Codec/version/ownership; Core never imports it. Persist root and nested Retry cursors: active resumes the same scope/index, confirmed failure precedes the next attempt, failed ancestors invalidate all descendants. Root Limit=1 prevents Resume replenishing exhausted budgets. Classify host interruption by the actual execution context, not an RPC's wrapped context error. All reliable failures share a tree latch and remain failures even when wrapping ErrSkipped or swallowed by an ancestor. Reject stream/channel declarations and actual channels hidden in nested interfaces, with cycle-safe value traversal; ordinary executions retain their previous behavior. Full contract: `docs/design/checkpoint.md`.
- **Host outputs (#321)**: `ReadOutput(e, k)` is a generic package function returning `(T, SlotState, error)` for this Execution's declared same-name/same-type outlet only. Read after Wait finalizes (also safe in GraphFinished); before finalization or on real failure/cancellation it returns no partial value. Normal ready/skipped/unfed optional pass-through pending have nil error; error makes both value and state invalid. It reads existing slots without waiting, allocating slots or emitting events; mutable values are shared, not deep-copied. Wait latches the terminal error/cancellation before setting done; repeated/concurrent Wait must not recapture its cleanup cancel (#327).
- **Execution views (stage 4)**: `e.Snapshot()` has no value option; GraphState includes this run's Execution identity, nodes follow definition declaration order, Child retains the latest created child Execution even on failure. States migrate before Observer callbacks, Retry does not regress them, and reads emit no events. Snapshot samples definition / runtime / slots under their own locks, without creating slots or holding locks across layers; it is not atomic and contains no business values. The graph becomes terminal when Wait finalizes it. `Topology.Graph.InPorts/OutPorts` includes all declared ports in first-successful-declaration order, including unused and pass-through ports; ordinary internal keys never become ports. `Topology.Mermaid(WithMermaidSnapshot(s))` derives structure solely from Topology, matches states by Graph ID + Path + Node ID, and samples live children separately. `yaml.Analyze(data, LoadOptions)` requires GraphID but no Registry, shares Load assembly, retains YAML type labels (empty for unknown), and never executes factories, resolves external seeds or calls ObserverFor. It does not validate host Go types or literal assignability.
- **Encoding primitives are frozen**: `AppendDuration` / `AppendTextValue` / `AppendAttrs` / `AppendAttrsExcept` / `AppendPadding` / `DisplayWidth` and the `LineRenderer` contract — the fragments a host egress builds from these six primitives are byte-identical to the corresponding fragments of the built-in layout.
- **Declarative graphs are YAML only** (`yaml/`): the YAML owns topology, the registered factory only supplies `Run`.
- **Secrets**: never commit `.env`, API keys or tokens.

## Freeze contract (0.x SemVer)

Breaking changes ride **minor** releases only, never a patch; each is listed at the top of its release notes. Frozen contracts: the slot contract (three states + skip-is-arrival), the `Aspect` shape and its advance gate (concurrent entry rejected; sequential re-entry legal only across a **fresh attempt boundary**), the sentinel errors (`ErrUndeclared` / `ErrConflict` / `ErrGraphStarted` / `ErrGraphNotStarted` / `ErrDuplicateSource` / `ErrSkipped` / `ErrNextCalledTwice` — the same list lives in `docs/design/pulse.md` under 附 · 冻结面), the `Observer` callback-count contract (two run-level + three per node, and "observer panic never becomes a node failure"), and the six encoding primitives + `LineRenderer`. Stage 2 changed the callbacks' **payload** (they now take a `Site` instead of a bare graph id) — a breaking signature change that rides a minor release; the **count** contract is unchanged. Stage 3 changed **semantics** instead of shapes: `Retry` re-entry no longer needs the caller to keep the failing attempt from writing (`ErrNextCalledTwice` gained its second trigger point, and a failed attempt's outputs are no longer visible) — no signature moved, but the release notes still call it breaking, because behaviour a caller could rely on did change.
