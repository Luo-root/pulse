## What this is

Go library (`github.com/Luo-root/pulse`) — a **graph engine** (a reusable `Graph` **definition** + one `Execution` per run) plus a **graph-observation layer**. Nodes declare which keys they read and write; topology is implied by data production and consumption (no edge objects, no topological sort, no scheduler loop).

The engine is the root package `pulse`; `observe/` folds the engine's `Observer` callbacks into structured records; `yaml/` assembles graphs declaratively. **The engine's dependency closure is zero** (standard library only).

## Build & test

```bash
go build ./...          # verify compilation
go vet ./...
go test -race -count=1 ./...
```

- Requires **Go 1.25.0+** (toolchain auto-downloads if missing).
- No Makefile or linter config. GitHub Actions CI (`.github/workflows/ci.yml`) runs `go build ./...`, `go vet ./...`, a gofmt check (empty output = pass), plus the `-race` suite on every PR and on pushes to `main`.
- **Markdown code blocks are not compiled** — when a signature changes, migrating only the Go call sites is not enough. `TestDocsExamplesUseCurrentSignatures` (root package) scans every tracked `*.md` for the entries this repo hands to readers: `New(` / `NewNode(` / `Sub(` (argument count, and "is the description slot actually a description" — `nil`, an option, a bind slice, a parameter-name placeholder all fail there); a `ctx` as `New`'s first argument (the pre-stage-2 shape — `New` no longer takes one); `Run(` with fewer than two arguments; a zero-argument `Start()` / `Wait()` whose receiver is not the execution side (a variable name such as `g`, or the `Graph` type spelled out in prose — `Execution` and the usual handle names are what pass); the first argument of the four seeding entries (`Seed` / `SkipSeed` / `SeedByName` / `SkipSeedByName` — it must be `&…`); and the deleted seed-source enum **where a reader could copy it** (package-qualified, or anywhere between code fences — a prose mention that says it is gone is history and passes). Migrate README (中/英), `site/`, `docs/design/` and the package READMEs together, then re-run it. Its own positive/negative controls live in `TestDocsExampleGateNegativeControls`, and the walk fails if it scans fewer than `scanFloor` sites (a gate that silently stops scanning is worse than no gate).
- No live-API tests and no network dependencies: `go.mod` requires only `gopkg.in/yaml.v3`.

## Key conventions

- **No `internal/` or `cmd/`** — this is a library, not a binary. All published packages are public API.
- **Chinese comments and doc are the norm**; preserve them when editing. **README naming**: `README.md` is the Chinese default, `README_en.md` is English — same for the root and every package (`observe/`, `yaml/`). The site builds from those two files.
- **Functional options pattern** throughout (`pulse.WithObserver()`, `observe.WithRenderer()`, `pulse.WithMaxRunning()`).
- **Dependency direction is one-way and must not reverse**: `pulse` ← `observe` / `yaml`. The engine never imports an observation package. Verify with `go list -deps .` — it must contain no other `github.com/Luo-root/pulse/*` entry.
- **Slot contract**: `pending` | `ready` | `skipped`. Skip is **arrival, not failure**; a node error cancels the graph and is never rewritten as skip. Unwritten `Provides` after a successful `Run` are auto-skipped.
- **Fan-in gate**: the gate is judged once every input has arrived (ready *or* skipped), and it asks "did any input bring a value" — a node enters `Run` as soon as one did (collect whatever arrives), and only skips itself when none did. A skipped input read inside `Run` yields `*SkipError`; returning `WaitAll`'s value is the explicit "all-or-skip me" opt-out.
- **Definition vs run (stage 2, landed)**: `Graph` is a **reusable static definition** — id / description / keys / producer table / ports / nodes / declared defaults — and holds **no** runtime state. Everything about one run lives in `Execution`: its own ctx and cancellation domain, input values, slots, per-node state, first error, waitgroup, and the **effective** observer / quota / graph-level aspects computed once at creation (this run's `ExecOption` > the definition's declaration > the parent execution's environment). `g.Run(ctx, in)` = `NewExecution` + `Start` + `Wait`, and it builds a **fresh** execution per call — so one definition can run many times sequentially, many times concurrently, and be mounted at several places at once. `ErrGraphStarted` now means "this **execution** was already started": slots never reopen, and a second run means a second execution. `New` therefore no longer takes a ctx. **Do not add a `Reset`**, do not put runtime state back on `Graph`, and do not add public surface that assumes `Graph.Child *Graph` — cross-run state belongs to the caller.
- **Inputs: the declaration is the definition's, the value is the run's (stage 2, landed)**: `DeclareInput(k)` is the definition's promise that `k` may come from outside; the value for *this* run goes into an `Inputs` value through `pulse.Seed(&in, k, v)` / `pulse.SkipSeed(&in, k)`. A nil `Inputs`, a zero `Key[T]`, a `nil` value, and a **second** write for the same key are all rejected at that call — the second write would be silently dropped by the slot's idempotent first write, which is exactly the mistake worth catching. `Run` / `NewExecution` then judge the **start condition**, and only that: every inlet some node `Requires` must be accounted for this run (seeded, skip-seeded, or bound with `In` in the parent). Feeding an undeclared key, feeding a key the graph itself produces, and missing a required inlet are all rejected there, by name, instead of hanging until the ctx expires. That per-run judgment runs **twice**: at creation (early feedback) and again inside `Start`, immediately before the seal — a definition can still grow a new `Requires` in between, and the definition that was judged has to be the one that gets sealed and run (see the Start-validation bullet). An inlet nobody `Requires` does not force the caller to feed it — this is a per-run criterion, separate from `Validate`'s "is this definition structurally sound". A **declared inlet is always a real inlet**: `DeclareInput(k)` on a key a node of the same graph already `Provides` is rejected at that declaration, and `Add`ing a provider for an already-declared inlet is rejected at that `Add` — one judgment from both sides, both wrapping `ErrDuplicateSource` (a port like that could only ever be dead, since the feed above is exactly what gets rejected).
- **Object model (`#311`)**: stages 1 (static composition) and 2 (the `Execution` split) are **landed**; what remains is transactional `Retry` (per-attempt write set, commit or discard). Each stage gets its own issue, its own PR and its own release; `docs/design/pulse.md` describes **what exists today**, while `docs/design/object-model.md` holds the target contract and the staged plan. Philosophy (why the trade-offs are what they are): `docs/design/philosophy.md`.
- **Composition is static — `pulse.Sub` is the only public entry (stage 1, landed)**: `pulse.Sub(g, id, description, binds, child)` mounts a **ready-made** child graph — ports (`DeclareInput` / `DeclareOutput` + `NewPort` / `PortRef`) are the *only* wiring surface, the whole subtree is visible **without running** (`Topology().Nodes[i].Sub`, path derived from the mount position), and the child's static problems surface at assembly time (in `pulse/yaml`: at `Load`, with the **mount path** in the message). There is **no** dynamic builder: the old `SubFunc` / `SubCtx` form is **deleted**, not renamed — a fresh child per run is what the stage-2 `Execution` now gives you (that is why deleting the dynamic form lost no capability). `pulse/yaml` builds one child **instance per mount site** at `Load`; at run time each mount site builds its own **child execution** (`newChildExecution`, ctx derived from that step's ctx, effective config computed from the parent execution's environment), so one child graph mounted twice runs **twice, independently** (own slots / first error / cancellation domain). Bind shapes are judged by `checkBinds` (shared by `Sub`, `Validate` and `Topology().Problems`): a child **inlet** may be bound with `In` **once** (a second `In` would be silently dropped by first-write-wins), and being bound through two entrances (`In` + `In`, or `In` + `Fix`) is the same "bound twice" error. **`Fix` / `FixSkip`** carry a value **for this mount site** — that is the only place a mount-site default can live, because it is not part of the child's definition (which is why the old seeding entry that took a child graph as its first argument had to go); a default *every* mount site wants belongs inside the child as a node that produces it. Binding an inlet the child produces **inside** is rejected at assembly time — `"k" is not a input port of the child graph` when the key was never declared an inlet (a key that only lives inside the child is its implementation detail) — and the state "declared inlet + produced inside" **cannot be built at all** (`DeclareInput` and `Add` reject it in both orders, `ErrDuplicateSource`; see the Inputs bullet), so `checkBinds` no longer carries that branch. Never a silent drop or a run-time surprise. `Out` is not deduped (two parent keys from one outlet lose nothing; the same parent key twice is rejected by `Add` as a duplicate `Provides`), so **`In(p, k)` + `Out(k, p2)` on one port is legal** — that is the pass-through (`k` declared as both inlet and outlet). `retry:` on a `graph:` node is rejected at `Load` — the bridge back into the parent happens inside the first attempt and those slots are idempotent first-write, so a retry has no clean set of its own (per-attempt write sets are the next stage); put the retry on the node inside the child that may actually fail. On the Go side `Retry(...)` on a `Sub` step is refused by **`Retry` itself, as the step's first act inside `Run`**: an `Aspect` cannot be identified at assembly time (it is a bare func type and a closure has no queryable identity — measured: `reflect`'s code pointer differs per instantiation), and letting it through would bridge the child's outputs into the parent twice, with the second attempt's writes silently ignored. A user-written retry-like aspect is caught by the step's own **entry-once guard** (which reports the first attempt's error too).
- **Sealing**: `(*Graph).Validate()` **seals the whole subtree** when it passes — and a successful `(*Execution).Start()` seals it as well (same rule, same critical section) — the mounted children are part of this definition, so `Add` / `DeclareInput` / `DeclareOutput` / `Sub` are rejected on **every** graph of that subtree (the second trigger point of `ErrGraphStarted`; the first is starting the same `Execution` a second time). A sealed child can still be mounted elsewhere (mounting does not change it) — and it can still **run** there: sealing freezes the **definition**, it does not consume it (`sealed` and `started` are now two questions about two different objects — the definition is sealed, the execution is started; `TestSealedChildCanBeReusedElsewhere`). A **failed** validation seals **nothing**, in no layer — that is what "add the missing piece and validate again" needs. Do not add a `Seal()`. Seeding is outside all of this: `Seed` writes into this run's `Inputs`, which belongs to no definition, so the step no longer keeps a run-time seed guard — what the child's inlet sees is the mount site's `In` binding or its `Fix` value.
- **Assembly is one critical section (`assemblyMu`)**: every definition-mutating entry (`Add` / `DeclareInput` / `DeclareOutput` / `Sub`) and the "check the whole tree, then seal it" entries (`Validate` / `(*Execution).Start()`) share one package-level lock, and it is always taken **before** any graph lock. Two invariants need it: the **mount cycle** (a cycle is the composition of two graphs' separate actions — checking and mounting must be one step), and the **validate → seal boundary** (the check pass takes and releases each layer's lock, so without the assembly lock another goroutine can rewrite a mounted child in between and `Validate()` would return nil while sealing a structure it never checked — measured, first trial). Corollary: **a sealed tree is exactly the tree that was checked**. Keep `Validate` and the start path holding it across both passes; a failed validation still seals nothing.
- **The static checks recurse with per-layer locking**: `Topology()` / `Validate()` hold the parent's lock and then ask each child through `child.problemsAt` / `child.topologyAt`, which take the child's own lock — never read a mounted child's fields while holding only the parent's lock (a test pins this under `-race`: `TestSubChildAssemblyVsParentReadOnly` — and `checkBinds` itself now takes the child's lock once for the whole batch, because reading the child's port table unlocked races `DeclareInput`; `TestCheckBindsReadsChildPortsUnderChildLock`). Corollary: when you already hold a child's lock, call the `...Locked` variants — `checkPortLocked` and `checkBinds` are **not** re-entrant. The recursion additionally carries the mount chain and reports a cycle instead of overflowing the stack or self-deadlocking on the child lock. It also threads **each layer's effective quota** (`effectiveCapacity`: this run's `ExecOption` at the root > a layer's own `WithMaxRunning` declaration > the inherited value), so a mounted child's stream-slot check is judged against the number that layer will really run with — otherwise the child was judged "unlimited" and the problem only surfaced in the child's own `Start`, after sibling nodes may already have run.
- **Declared outlets are checked statically** like inlets: `DeclareOutput(k)` where nothing in the graph provides `k` (and `k` is not also a declared inlet — an inlet/outlet pair is a **pass-through**) is reported by `Validate` / the start path / `Topology().Problems` at assembly time, naming the mount path when the graph is mounted, instead of waiting for `bridgeOutputs` to say `never arrived` after the child ran. A declared inlet for a key the same graph produces is rejected where it is declared (`ErrDuplicateSource`) instead. `Problems` order is sources → declared outlets → dependency cycles → streams → per-mount subtree; the outlet category is ordered by key name (map iteration must never reach a message).
- **In `pulse/yaml`, a spec nothing references is *not* judged for sources**: it has no mount site, hence no interface — "nothing feeds this key" is undecidable there (any key with no source is assumed to be an inlet, declared into a build-only throwaway check graph), so such a spec is checked for factory names / empty nodes / duplicate ids / source conflicts / cycles / streams only. Sources are judged per **reference site** once the spec is actually mounted.
- **Aspect latch**: a node's `Run` must not be entered concurrently (overlapping `next` → `ErrNextCalledTwice`); sequential re-entry is legal and `Retry` depends on it.
- **Start validation**: starting an `Execution` rejects the statically-knowable dead graphs — a `Requires` with no source, a **declared outlet nobody produces**, and a dependency **cycle** (every input has a producer, yet no node can run first). The **per-run** half of the story (every required inlet has a value for *this* run) is judged when the execution is created **and re-judged inside `Start`, immediately before the seal** — same criterion, word-for-word the same message. The definition can grow a new `Requires` in between (`Add` is still open), and `Start` is about to seal the very definition it judged, so "judged = sealed = actually run" stays one version. A rejected start still marks nothing started and seals nothing (feed the value and run again). Without those checks they surface as a hang, or as the runtime's fatal all-goroutines-asleep deadlock (or, for the outlet, as `never arrived` only after the child ran). A cycle is reported as one concrete path: `pulse: dependency cycle: A -> B -> A (A requires "y", B requires "x")`.
- **Observation**: every callback carries a `Site` — the definition's graph id, **this run's execution id**, and the mount path — so the same graph run twice, or mounted at two places, never folds into one set of records. Business dimensions go through `Attrs` only — **never add named fields to `Record`**. Attr keys use the `<component>.<field>` convention and are defined by the package that owns the fact (`pulse.AttrGraph` / `pulse.AttrNode` / `pulse.AttrExecution`).
- **Encoding primitives are frozen**: `AppendDuration` / `AppendTextValue` / `AppendAttrs` / `AppendAttrsExcept` / `AppendPadding` / `DisplayWidth` and the `LineRenderer` contract — the fragments a host egress builds from these six primitives are byte-identical to the corresponding fragments of the built-in layout.
- **Declarative graphs are YAML only** (`yaml/`): the YAML owns topology, the registered factory only supplies `Run`.
- **Secrets**: never commit `.env`, API keys or tokens.

## Freeze contract (0.x SemVer)

Breaking changes ride **minor** releases only, never a patch; each is listed at the top of its release notes. Frozen contracts: the slot contract (three states + skip-is-arrival), the `Aspect` shape and its re-entrancy latch, the sentinel errors (`ErrUndeclared` / `ErrConflict` / `ErrGraphStarted` / `ErrGraphNotStarted` / `ErrDuplicateSource` / `ErrSkipped` / `ErrNextCalledTwice` — the same list lives in `docs/design/pulse.md` under 附 · 冻结面), the `Observer` callback-count contract (two run-level + three per node, and "observer panic never becomes a node failure"), and the six encoding primitives + `LineRenderer`. Stage 2 changed the callbacks' **payload** (they now take a `Site` instead of a bare graph id) — a breaking signature change that rides a minor release; the **count** contract is unchanged.
